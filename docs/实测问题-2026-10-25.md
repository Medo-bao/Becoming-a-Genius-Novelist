## 根因与本轮修复

### 1. 工具限制放错作用域

DSH预设先挂载到共享generation作用域，agent随后以该generation为父作用域。本机已安装ASAR的tools.view把“当前作用域自己的工具”和“继承工具”分开：restrict只能引用继承工具，而其过滤结果也会影响后代agent。

因此1.0.0在预设作用域设置allow: []，从worker实例看，预设的五个文件工具都是被过滤的继承工具，最终请求没有tools。仅改成allow五工具同样不正确：在预设本层校验白名单时，这些名字不是可限制的继承工具，会抛unknown global tools。

本轮改为监听宿主agent/created，在agent.ctx.tools上设置native展示与五工具白名单。此时五个文件工具确实来自父预设，允许名单可校验，也不会清空工具。注册的释放函数同时归属钩子生命周期，避免卸载后留下限制。

### 2. 队长绕过登记直接写稿

1.0.0的旧正则没有覆盖正文改编/章节/476.txt。工作区已有修正扩大了目录匹配，但roots.size > 0又把“会话里找到任何项目”当作“目标已登记”。

上轮先按目标所属项目修正了该判断。本轮继续收权：DSH队长不再提供任何直接write/edit、shell或run_code，原生fs写入事件同样拒绝；因此A/B项目和自定义目录均不能靠原生文件工具绕过。正式制作只经novel_workshop调用原有核心，未登记时不能dispatch；元数据用config/record等保存，策划文档由岗位产物collect提交，保留制作能力。

### 3. 从提示约束补齐到实际执行约束

补充“未登记先import”“材料缺失停下”“不轮询”的提示有帮助，但记录显示队长会主动要求工具失效的worker继续交稿，并把同一文笔切成审稿人。真正的正式提交仍须依靠任务绑定、collect动作校验和独立复核身份检查，不能靠聊天里自称通过。

本轮已提供novel_workshop专用工具，直接复用CLI同一份程序入口，不启动shell，也不使用命令字符串黑名单。队长的通用shell、直接文件写入、手动subagent/workflow和send_message入口同时从工具面与执行守卫移除；仅保留11个制作、只读材料、作者交互及状态工具。worker保留五个文件工具。

| 实测问题 | 本轮约束 | 验证结果 |
|---|---|---|
| worker零工具、输出伪DSML | 在实例创建时设置native与白名单，并检查必需工具确实可见；缺失即停止启动 | 本机ASAR作用域函数验证通过 |
| 未登记却开始写稿、运行旧项目脚本 | 专用dispatch加载真实登记；队长没有shell或直接写入入口 | 未登记派单与shell/文件写入均被拒绝 |
| 省略dispatch/task绑定 | dispatch内部建单、预留真实UUID并绑定，再启动固定worker预设 | 启动前已有running绑定，伪造running/agent被拒绝 |
| 无文件读取仍内联交稿 | 记录真实read成功回执与分页覆盖；任务单、岗位卡、textFiles、复核材料包/正文必须读完 | 无回执、只读一页或覆盖输入均被拒绝 |
| 队长把聊天正文直接落盘 | 无直接写入工具；collect只读任务结果，并要求宿主在任务目录外保存的阅读回执 | 聊天补交的假result文件无法收件 |
| 同一文笔写五章后自审 | 每次dispatch启动全新ID；不提供send_message追加任务；核心仍检查文笔/复核身份 | 两岗位实际绑定不同ID，独立复核提交通过 |
| 覆盖旧稿及绕过正式验收 | 只通过原有collect写入新版本、维护两更和提交复核 | 原有版本、证据、范围与尾批测试全部保留 |
| Start-Sleep轮询等待 | 没有shell/run_code；启动返回waiting，使用宿主完成通知 | 禁止工具调用被拒绝，无定时脚本入口 |

阅读回执由worker钩子记录，保存于任务目录外的受管位置；worker不能覆盖任务输入或伪造回执。收件仍检查任务依据是否变化。回执证明实际工具读取及分页覆盖，不代替复核对文学质量的判断。

## 流程精简

- DSH的建单、原生启动、ID绑定由一次dispatch完成，消除手动绑定竞态和额外send_message。
- collect与其他状态变更直接附下一步diagnosis，模型不再额外执行一次doctor；派单已经提供材料和复核草稿，不重复prepare/accept。
- 结构化参数直接作为data传入同一核心，不写临时JSON、不启动额外Node进程；Codex和人工CLI仍保留。
- 文笔派单复用刚完成的写入就绪诊断，避免生成context时再做一次全项目诊断。
- 原作汇编导出先读取、解码底本一次，再逐章切片；由“每章重读全底本”改为一次读取。格式、字数口径和章节内容不变。
- 删去不用的正文路径识别旧代码及队长jobs/present插件。独立复核、尾批、校准、事实/授权检查、版本保留和TXT/DOCX/EPUB交付均保留。
