# 1.0.1 补充修复与优化

版本说明：本文件名保留当时本地1.0.3工作标记，供既有会话链接使用；所有修复已按用户要求归并1.0.1，当前版本与安装包均为1.0.1。最终检查见[1.0.1验收记录](1.0.1验收记录.md)。

日期：2026-10-26。基于 1.0.1 DSH 实测及 1.0.2 调用链复查，修复材料与问题复验闭环，减少重复读取、计量调用和无效派修。原始会话、小说正文及小说主账未修改。

## 已完成

| 问题 | 处理 |
|---|---|
| 同册切片遗漏其他册的直接关联 | 从明确章节映射、当前细纲同目录 Markdown 查找对应章段，按文件合并提供 relatedOutlines；不递归展开关联链，缺少明确关联时列出 missingRelatedChapters |
| 通用编号文档被误当章节 | 03-大纲.md、04-文风.md 不再因编号被当作第3、4章；无章节标题时仅使用明确映射、“第N章”文件名或纯数字文件名 |
| 局部复核覆盖跨章问题的待验基线 | 从已有审阅历史逐章找最近观察版本，不再依赖单个 reviewedBy 指针；纯审阅模式同样按章判断 |
| 跨批问题反复局部复核，无法关闭 | 自动合并相交问题的完整、已写且已授权范围；已修待验无需等批次写满；范围超出授权时返回 review-scope 及 ranges |
| 模型忘记调用计量工具 | DSH 文笔成功写入或编辑 result.json 后自动收到宿主计量，包含实际汉字数、相对当前稿差值及原有篇幅政策；单独草稿保留 novel_draft，Codex 保留 draft-check |
| 已修内容回退、前后复核修法冲突 | 材料包加入 resolvedIssues 摘要；复核指引要求查依赖章当前稿相关片段，推翻旧修法必须解释具体证据变化 |
| 返修提示同时要求 text 和 patches | 按任务动作给出唯一默认提交形式，返修默认 patches，整章重写才提交 text 与 rewriteReason |
| 补跨册材料引入重复读取 | 派单、批次材料与单次诊断共用临时读取缓存；不跨操作保存旧内容、不增加哈希 |

明确跨册依赖加入已有审阅依据记录，发生变化后只使相关结果失效。自动补入的相邻章仅作阅读参考，后续新建相邻章细纲不会无故让已通过批次重审。

自动计量不修改正文、不自动凑字数，也不新增“计量回执”门槛；格式不完整时保留已写文件并反馈具体原因，由同一文笔继续修正。计量及提示不能替代内容判断。

## 供应商 schema 约束

`novel_workshop` 的参数曾尝试用根 `oneOf`/`anyOf` 表达17个动作，但 OpenAI 兼容供应商要求 function 的 `parameters` 必须是 `object` 根；根级联合类型会以 `Invalid schema ... not valid under any of the schemas listed in the 'anyOf' keyword` 整单拒绝。现恢复为 `type: object` + `action/project/options/data`，`action` 保留17值枚举；具体动作的字段仍由 `validateCall` 检查，`options/data` 的 `description` 自动列出各动作支持的键。测试新增 `assertDshSchema` 并断言根为 object、无根级 `oneOf/anyOf`，同时覆盖 `novel_workshop` 与 `novel_draft` 的输入、输出 schema。

真实小说资料只读核对：第478章补齐第565章（约1461字符）；第479章补齐第263、413、585章（分别约1432、1458、1431字符），missingRelatedChapters 均为空。读取未触发派单、写作、收件或主账更新。

以上是工程验证与真实材料读取验证，没有调用在线模型；总写作耗时、返修轮数和文学质量仍需新版实际运行记录确认。

## 使用

安装本轮重新生成的 1.0.1 bundle 后重启 DSH，使新预设及 worker 加载。接手既有项目先 doctor，沿用真实当前稿和已完成产物，不重新重写五章。已运行的旧 worker 不会自动切换新协议。
