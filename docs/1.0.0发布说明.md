# 1.0.0

首次正式版本。核心目标是自动诊断小说制作状况，在一个主会话中由队长派发六岗位子代理，完成授权范围的制作与交付，减少作者主动干预。

## 本轮修复

- 任务产物和内部项目状态检查路径分量，拒绝符号链接与Windows目录联接；产物读取后按原字节提交，保留UTF-8 BOM。显式选定的外部底本仍可只读使用，自定义受管目录保留。
- 复核问题必须完全属于本次被审章节，规范化保存from/to，证据绑定当前被审正文，避免越界或省略to后漏诊。
- 批次校准结果不能进入作者专属的熔断恢复分支，作者恢复由队长依据真实新决定单独登记。
- 先校验完整校准结果和所有产物，再提交文件；校准和细纲动作只允许指定章的准确细纲路径，新细纲可与复盘一起提交。
- 普通review不能自行签发final验收，只有final-review可以签G5。逐章检查必须是布尔值，机械字数与比例由工具产生。
- DSH派单固定独立worker preset，worker不提供shell、再次委派或作者交互工具，写入绑定实际子代理ID与当前任务。当前不能选择受限worker的DSH workflow入口停止提供，使用原生subagent完成六岗位分工。

复核任务由队长预先生成逐章材料包，worker直接读取，无需运行CLI；长文本和正文提供可按行分页的UTF-8阅读视图，避免原生读取工具的单行截断，也覆盖GB18030底本。使用宿主workingDirectory实际目录查找项目，不依赖可能仍指向父会话目录的header.cwd。生成全书材料时复用底本读取，不逐章重复进行完整项目诊断。首次缺项询问、版本保留、尾批审阅、暂停恢复以及TXT/DOCX/EPUB交付继续保留。

## 使用

Codex按README安装项目技能；DSH安装本地bundle后选择“我要成为天才小说作家”，不要把岗位worker当作者主会话。已有小说升级安装不重建project.json、不覆盖正文或继承虚假验收。

ZCode专门适配仍待后续，不宣称具有当前DSH的工具权限边界。
