# 使用说明

当前版本：1.0.2。此前1.0.1阶段的功能和调用限制保持。

> 英文名：**Genius Novelist in the Making** ｜ 中文名：我要成为天才小说作家

仅在明确调用`$tiancai-novel`、点选本插件或明确要求使用「我要成为天才小说作家」插件后启动工坊；DSH主动选择同名预设也属于明确调用。普通写小说、续写、精修、查看进度、泛称使用插件或使用其他插件均不自动调用。安装和维护插件本身不启动小说制作，旧scope不授权新任务。Codex的技能策略设置allow_implicit_invocation=false，项目规则也保留该边界。

明确调用后作者只用一个主会话。队长先doctor诊断，再派相关岗位子代理执行、收集提交，直到授权完成、暂停或确需作者裁决。队长不写正文，正文由文笔子代理创作；本次目标结束后不向后续请求沿用调用状态。原生Codex安装与项目部署方式见[Codex适配](Codex适配.md)。


## DSH自动续作与报告修正

DSH本会话明确scope后，成功collect会自动按当前诊断启动下一岗位，返回continuation时只等待该单完成通知，不重复dispatch或结束等作者催促；未自动启动才执行nextAction.call。自动续作只作用于本会话当前scope，不在scope初次保存时跳过前置资料同步，也不越过configure、作者裁决、导出等动作。scope.options.automatic=false改为手动派单；暂停、只读或中止清除本会话续作状态，获准恢复时重新scope。

复核保存result.json即获得只读预检。issues每项必须含非空text及evidence:{path,quote}，passed的各维grade为A/B并有真实reason；“良好/合格”不能代替字母，程序不替代理抬分。quote用当前稿逐字连续短句，不拼接、省略或补引号，无需整段对白。字段或引文错误保留原单，由原复核代理修同一报告；DSH collect自动回叫原代理，correct-result可恢复，最多3次，不标failed或由队长重建issues。新写作、返修及实质复核仍用独立任务；材料/正文变化则按受影响范围重新审核，不借字段回修绕过。原代理保留自己已验证的完整阅读回执，回修先读prompt/context/岗位卡及原result.json，仅能写result.json；新代理仍须完整读取。

Codex使用`novel result-check <项目> --task ID`只读预检，原复核子代理修正字段后再collect；不会自动追认旧报告或启动小说制作。

## 归档与调度优化

新增目标完成归档：最后收件/交付后自动分类移动到`.novel-workshop/archive/goal-r版本-编号/`，归档清单列出原、新位置；历史任务按task --id查询。`archive --preview`只读预览，`archive`手动归档既已完成目标；未完成/暂停/存在未收件任务时不移动，inspect只读保持原状。额外临时资料用record material temporary:true及category:temporary/cleanup/research登记；config.autoArchive=false关闭自动整理。当前引用、正式稿各版本、规划、报告、交付物、运行与宿主指令文件保留。

dsh3补充：新会话仅读取docs/确认进度时调用novel_workshop {"action":"doctor","options":{"inspect":true}}，或CLI doctor --inspect --json；待办只作报告，不修登记、不派finish。明确恢复制作后inspect=false。同一制作中的进度询问不切换只读模式。工具修复参数必须为options.fix，根级fix会报错；数字TXT的版本按已登记准确路径识别。返回currentChapters和latestReview，直接区分当前稿待验与历史版本通过。

1.0.1阶段修正范围缩小误取消、跨章范围漏记、起草碎片化、重复选册/大目录返回、漏读与参数试错、旧进度未同步。程序保留有效任务与真实阅读回执；暂停、越界、权限/间隔/依据改变仍取消。跨章标题声明和affectedChapters归并到完整from/to，后章未修时不会提前关账。

config新增outlines范围绑定及progressFiles已有进度路径；doctor只返目录摘要，documents默认10项分页，阅读底稿与正文片段不抢占执行资料。requiredReads列齐任务输入，漏读一次报齐。DSH公开字段类型/枚举与动作示例，诊断提供nextAction.call。文笔完整起草并集中修订，完整MD/TXT可用draftFile替代text；复核不回抄contract/stamp，同批前章全文已提供时不重复其尾段。实际全文读取、独立复核、引文、版本与依赖校验均保留。

原有进度文件只替换工坊当前状态段，作者原文/BOM和历史保留；未变不重写。DSH/Codex同源支持，无新增运行依赖。

绑定示例（先实际读取资料，数字仅说明格式）：

```json
{"action":"config","data":{"outlines":[{"path":"docs/现行分册细纲.md","from":481,"to":483}],"progressFiles":["docs/项目进度.md","docs/现行要求与执行计划.md"],"source":"已核实的现行执行依据及文档维护规则"}}
```

已有完整草稿：`{"draftFile":"完整草稿.md","title":"实际标题","notes":"实际注意事项","experience":"实际经验","exitState":{}}`；草稿必须在本单目录，不能引用输入材料。text、draftFile、patches互斥，返修整章仍需rewriteReason。

## 新书与既有小说

新书从已有设想建立规划。首次核对模式、全书计划章号、篇幅政策（固定目标或按底本）、审查间隔是否有明确依据；先查现有资料，缺项集中一次询问，保存答案与来源。默认4000字/5章不代表作者已规定，参数已明确后不重复问。已有小说先扫描目录，用import登记原稿、章号、底本和既有资料；保留原文件，历史通过声明不继承。支持0号引子、数字TXT/MD及版本化章稿。

接手后读取现行要求、最近目标变更和计划，记录有效要求及其来源。曾被替代的第一版方案不恢复为当前依据，助手过去的“已批准”不等于作者实际批准。若会话工具未提供目标变化，用现行项目材料核实并说明缺口。

已有文档现在可按用途、标题和目录检索，包括自定义资料目录中的MD/TXT。DSH使用novel_workshop的documents动作，Codex使用CLI documents；先查看检索线索，再读取相关原文。导入会复用明确路径或唯一匹配的人物、世界、文风、大纲、经验与注意事项文件；多版本候选由代理回查现行要求后config绑定，文件存在不代表内容已批准。只有规划文档、尚未写正文也可import，不需要重建一套模板。

策划默认在原文件局部补充；现有成果足够时不创建新文档。确需独立的同用途补充文件须说明createReason，派单后作者改过原文件则拒绝旧结果；原样成果跳过写入。现有分册细纲按章直接复用，注意事项与经验合用一份文件时两项内容合并保存。必要任务目录和生成状态仍保留，不自动删除历史文档。

## 自动制作如何运行

doctor输出阶段、实际进度、授权、失效审阅、待办与nextAction。队长dispatch建单，调用宿主原生子代理，绑定实际执行者，collect后回doctor。主编、世界、剧情、人物、文笔、复核按需分工；相互独立的分析可并行，依赖前章的正文顺序制作。子代理只写各自任务目录，正式产物与主账由队长串行提交。无需作者逐步发消息。

DSH固定使用独立岗位worker预设，队长通过novel_workshop专用工具自动建单、启动、绑定和收件，不提供通用shell、直接写文件或手动追加代理消息。worker只提供读取、搜索与任务目录写入工具，必须实际读完任务材料才能提交；复核所需材料由队长侧工具生成，长正文和底本提供可分页的UTF-8阅读视图。collect直接返回下一步诊断，无须再次doctor；没有结果文件或真实阅读回执时不能用聊天正文补交。升级bundle后重启DSH，以新worker接续。

已有稿仅缺两更时，finish按doctor给出的chapters批量补记录，当前正文完整读取，不复制、润色或提交正文补丁；补登记不增加审阅通过。保存结果后宿主直接计量现稿，正文问题交独立复核后另派repair。作者恢复或改终点时先scope保存最新范围与来源，再派单，不让旧停止点覆盖新目标。

DSH从只读确认恢复时，先doctor options.inspect=false，再立即scope保存新范围，再执行待办，手册只读runtime实际路径。复核逐章填verdict，未受影响的独立通过章保留结论，改稿与直接依赖仍复验。按底本且未设比例时不自行补到95%；排版返修用format的heading/indent，不重抄整章。计量comparison区分内容与格式变化，字数相同不证明文字相同；复核可只读复算本单当前正式稿。

当前DSH文笔写入或编辑result.json后自动收到准确字数反馈，无需重复调用novel_draft；单独草稿仍可用该工具，Codex用同源draft-check。返修收到本轮当前稿和已解决问题摘要，默认局部修改并保存新版本；独立复核逐项提供解决证据，程序按章追踪已修待验状态。跨册直接关联材料自动补齐，跨批问题按完整已授权范围复核；review-scope表示所需范围超过当前授权。具体改动见[迭代记录](迭代记录.md)。

普通问题在授权范围内自行修复。剧情根本取舍、关键缺失信息或确实超出授权的动作，集中给出证据和推荐选项再询问。review范围只审不改，pause保留暂停；终点变更立即生效，末尾不足一批只审实际尾章。

## 权威状态与自动维护

`.novel-workshop/project.json`保存配置、实际章稿版本、有效授权及历史、底本索引、要求、事实、问题、经验、审阅和交付记录。`00-状态.md`与工坊内当前要求摘要自动生成，避免人工同步多份当前计数。

文笔结果经collect创建新版本并更新两更、经验与出章状态；中断后可派finish补齐回执。恢复先核对已有任务和宿主状态，已完成未收集的先收集，执行者丢失的记录后重派，不重复提交。磁盘遗漏稿可用doctor --fix补登记，不因此增加验收。外部改动使旧版本失效，核实后另存新版本。

## 事实与改编

prepare提供本章底本及行号、细纲、前章尾段、入章状态、相关人物和事实、有效要求、到期伏笔与当前问题。事实记录带章区间、实体和真实出处；原作事实与当前改编规则分别识别。

改编支持保留、改写、合并、删除、新增、校正、联动；保留原始分类，升级必要补改时不伪造基线完成数。篇幅比较排除标题，正文和底本使用相同汉字口径。未指定固定比例就只显示数据，由内容审阅判断场景、信息与节奏，避免凑数。

## 复审与返修

复核任务提供accept草稿，必须由与文笔不同的子代理实际冷读、填写，再经collect提交。原创审阅三项，改编再含改编符合性、删改合理性和文风一致性；每章需真实引文和实际检查，改编需说明篇幅判断。填满表格不能证明文学质量。

rework的问题自动入账，可修复、撤销误判或由新依据替代，需说明及证据。审阅绑定正文、要求、事实、细纲、底本映射、入章状态及依赖章版本/出章状态；依据变动后只复验受影响章。历史报告保留，不冒充当前结论。

待裁决破格、当前范围内连续返修熔断、未完成批次校准都会阻止继续写；不能只跳过doctor。每批通过后派剧情子代理核对当前授权内下一批细纲，登记校准再继续。熔断恢复要记录作者新决定与具体章号，其他范围的旧问题不阻塞本轮任务。

## 交付与格式

| 产物 | 选择条件 |
|---|---|
| partial阶段稿 | 明确章号范围，每章有有效通过版本，文件名含范围 |
| final正式全书 | 全书连续完整、当前版本最终审阅通过、问题闭合 |
| source原作底本 | 来自登记底本与索引，不混入改编正文 |
| analysis原作提炼汇编 | 只采用已登记为原作来源的分析资料，不混入改编方案 |

格式为TXT、DOCX、EPUB、Markdown，默认全部，也可组合选择。TXT使用UTF-8 BOM和Windows换行；Word为可编辑文字、章节链接目录、分页与页脚页码；EPUB含导航、元数据与可选PNG/JPEG封面。重复导出递增版本，目录记录采用的文件。

完成判定核对实际文件；记录存在但产物丢失时会重新安排交付。底本或资料丢失返回明确恢复事项，先恢复来源或核实路径，再继续依赖它的制作。

全书最终审阅与批次复审分别记录。原作分析Word不等于改编全书交付。所有格式使用同一组已选正文，不凭导出成功宣称全书内容验收完成。

数据与命令示例见[自动制作协议](../core/自动制作.md)。
