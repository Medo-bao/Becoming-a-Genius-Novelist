# 我要成为天才小说作家

一个作者会话由队长协调，主编、世界、剧情、人物、文笔、复核各由独立子代理执行。队长不写正文，也不在同一上下文轮流扮演岗位。

## 先读

DSH 预设把运行资产同步到 `$DSH_HOME/novel-workshop/`，未设置时为 `~/.dsh/novel-workshop/`。使用其中的 `bin/novel.mjs`、`core/手册.md` 与 `core/自动制作.md`。项目安装版使用 `<项目>/.novel-workshop/` 内同名路径；若直接从本源码使用，读本技能包根目录的 `core/`、`bin/`，不要把技能目录误作运行目录。

队长先读核心流程和已有项目 `00-状态.md`，运行 `doctor <项目> --json`。子代理先读分配的任务提示与对应 `core/roles/<岗位>.md`，只执行自己的任务。

## 首次检查参数

`doctor` 的 `configure` 会给出 `missing` 与问题列表。先从用户原话和明确的项目文档补齐已知项；在 DSH 用 `ask_user_question` 只把剩余缺项集中问作者，不把初始默认值当作已确认。

- 渠道：原创或改编精修。
- 计划：起始、终止章号或总章数；执行终点另用 `scope` 保存。
- 篇幅：原创章均目标，或改编随底本的规则；仅在作者规定时设置比例范围。
- 审查间隔：按多少章复核；停止点处仍复核不足一批的尾章。

收到回答以 `config --source "用户原话或明确文档依据"` 保存对应值。缺项未确定时停止依赖它的制作，不先按经验填数。已有确认项不重复问，后续新指令覆盖旧值时记录新依据。

## 派单与收件

| 岗位子代理 | 负责内容 |
|---|---|
| 主编 | 制作目标、立项、阶段方案和裁决建议 |
| 世界 | 世界规则、事实与设定冲突 |
| 剧情 | 总纲、细纲、接续和批次校准 |
| 人物 | 人物动机、关系与行为一致性 |
| 文笔 | 正文、返修及章末状态、注意事项和经验 |
| 复核 | 独立冷读、真实引文、评分和问题判决 |

1. 队长按 `doctor.nextAction` 创建 `dispatch`，选实际需要的岗位和章节范围；批次可用 `--chapters` 逗号列表精确指定。参数未确认时不能派单，不要为凑齐六人派空任务。
2. 把输出的绝对 `promptPath`、`contextPath`、`resultPath` 和项目路径交给全新 `subagent`；DSH 的 `cwd` 使用小说项目根目录，`description` 使用任务编号，`prompt` 指明岗位并要求读任务单。DSH 派单固定独立的 `tiancai-novel-worker` 预设，不继承队长工具或改选其他预设。独立分析可以同时启动；正文每单只派一章，收件并取得实际出章状态后再派下一章。
3. 从宿主启动结果取得真实子代理 ID，用 `task --id <任务编号> --status running --agent <真实子代理ID>` 立即绑定；DSH 使用返回的 `subagentId`，绑定后用队长的 `send_message` 通知它继续。worker 未绑定时不能写，需保留任务并向队长报告。槽位不足时分批派单，不退回队长写正文。
4. 子代理只写自己的任务目录：策划提交 `summary` 与 `artifacts`，文笔提交 `title/text/notes/experience/exitState`，复核按 `accept` 草稿格式填真实证据；具体以任务提示为准。子代理不改 `project.json`、全局文档、正式细纲或正文，不运行测试。
5. 队长等宿主确认完成，依次 `collect --id <任务编号>` 校验收件、提交文件和状态，然后重新运行 `doctor`。队长不代写或改写结果中的正文；需改稿就重新派给文笔。
6. 文笔与复核必须是不同子代理 ID，原稿 authorAgent 与复核代理相同会被拒绝。复核发现的普通问题按授权派文笔修复、复核复验；作者取舍、破格裁决或达到返修上限时集中询问。失败或取消时用 `task --id <任务编号> --status failed|cancelled --reason <实际原因>` 登记，保留结果后重新派发，不收件为成功。`scope` 变化会取消未完成任务，旧结果不能直接继续收件。

正常流程统一 `collect` 提交；原始 `write`、`finish`、`review` 必须携带 `--task`，仅用于已绑定任务的故障恢复，不能绕过派单直接写作。

DSH 队长预设启用原生 `subagent`（spawn，全新上下文）、`send_message`、`interrupt_agent`、`list_agents` 与后台任务控制。岗位 worker 仅提供 `read`、`glob`、`grep`、`write`、`edit` 和自动压缩；全局宿主工具被隔离，不提供 shell、代理控制、询问作者或再次委派。每次写入都核对真实会话 ID、父队长、当前 scope 和 running 任务，只能落在绑定的任务目录，符号链接和目录联接不能跨过该边界。模型选择继承宿主，不为岗位擅自指定新模型。`list_agents` 由队长找回已派发代理，完成通知到来后收件，不轮询制造空转。

当前 DSH 的 workflow 后端不能固定 worker 预设，本版关闭该入口。多岗位仍由队长按依赖和槽位直接调用原生 `subagent`，独立任务并行、共享目标串行，再逐项 collect；没有真实委派能力时报告能力缺口，停在派单阶段。DSH worker 不执行 CLI：`dispatch` 的 review/final-review 任务由队长侧生成逐章 `chapters/NNN.json` 材料包，`context.packets[{chapter,path}]` 指向细纲、底本、要求、事实与前章内容。长文本移到 `textFiles` 列出的 UTF-8 阅读视图；逐章正文读 `manuscript.path`，使用原生 `read` 的 `offset/limit` 分页，避免单行截断。证据路径仍填 `originalPath`，引文不跨阅读视图插入的换行。队长只整理输入，不代填正文或审阅结论。worker 缺包或缺资料时在最终回复向队长说明具体缺口，请队长补料或记录阻塞，不自行询问作者或以 shell 兜底。

## 持续制作

- G0 立项 → G1 人设、大纲、文风 → G2 总纲要 → G3 细纲 → G4 逐章 → G5 成书；阶段依据入库后才推进。
- 文笔使用 `prepare` 提供的细纲、底本切片、入章状态、有效要求、事实与经验；章末提交实际两更和出章状态。
- 原创按已规定的章均判断；改编按映射底本与删改理由判断，不擅设篇幅比例或凑字数。
- 按当前 `scope` 的审查间隔和实际停止点安排独立复核；范围缩小或暂停立即生效，不逐章重复索要已有授权。
- 批次通过后由剧情子代理完成范围内校准；破格待裁决或返修熔断时停在对应动作，不能绕过继续写。
- 压缩恢复先运行 `doctor`，核对仍在运行、已完成待收件与失败的任务，继续原任务或收件后再派新任务。
- 正文不贴聊天，只汇报简短摘要、文件路径、字数、判决和当前必须由作者决定的问题。

## 工具

```bash
node bin/novel.mjs doctor <项目目录> --json
node bin/novel.mjs config <项目目录> --source "作者明确规定的值" --mode 原创 --start 1 --end 120 --length fixed --words 4000 --interval 5
node bin/novel.mjs dispatch <项目目录> --role 文笔 --action write --chapter 1
node bin/novel.mjs task <项目目录> --id <任务编号> --status running --agent <真实子代理ID>
node bin/novel.mjs collect <项目目录> --id <任务编号>
```

示例数字只说明命令格式，不能代替作者尚未作出的参数选择。`bin/novel.mjs` 应替换为已确定的运行资产绝对路径。ZCode 专门适配仍留待后续，不能以本技能的存在宣称已经接通其子代理能力。

## 不要做

- 队长写正文，或把同一上下文自评当独立复核
- 子代理并发修改项目登记和正式目标文件
- 缺少参数、细纲或授权时开写，或绕过诊断的阻塞动作
- 覆盖正文旧版本，或未经授权回改已验收章节
- 把失败、取消、未完成的委派收件为成功
