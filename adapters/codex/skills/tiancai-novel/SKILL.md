# 自动小说制作

## 调用边界与运行入口

只有本次目标已被用户明确指定使用本插件才执行以下流程。仅看到小说目录、旧scope、正文文件，或收到写小说、使用其他插件、查看进度的普通请求，不调用本技能、不运行CLI、不派岗位任务，也不自动安装项目规则。安装或维护插件本身不启动制作。明确调用后在该目标内持续执行；目标完成、取消或用户转向其他工作后结束本次调用，不给后续请求自动续用。

本技能随附[CLI入口](../../../../bin/novel.mjs)、[制作手册](../../../../core/手册.md)、[派单协议](../../../../core/派单.md)与[CLI 协议](../../../../core/自动制作.md)。以当前SKILL.md所在目录解析上述CLI链接，得到实际绝对路径；不要从当前工作目录或小说项目名称猜程序位置。原生插件链接到包内bin，项目安装器会将链接改为本项目.novel-workshop/bin，两种安装均沿用该链接。下文`<运行入口>`和`<小说项目>`分别替换为解析出的CLI及目标项目的实际绝对路径。原生插件不因项目未部署程序而额外复制技能或新建项目规则。

## 开工与参数

只读本Codex专用入口，不再叠加共享技能的DSH流程。先解析上方CLI链接；`.novel-workshop/`存在不代表其中部署了bin/core，以实际安装的链接为准。doctor返回runtime的CLI、手册与协议绝对路径，后续沿用它们；向岗位传context.runtime中的真实入口。

常用doctor、dispatch、collect、task、scope、config统一加`--compact`。回包保留任务路径，收件/范围变更直接给diagnosis.nextAction；按该诊断续作，不再另跑doctor，也不截取前几行丢掉结果路径。完整材料读context/result文件，完整诊断可省略--compact。PowerShell解析JSON用ConvertFrom-Json；确需Python时用`python -X utf8`并显式处理UTF-8，不经默认编码管道反复解析中文路径。

明确调用本插件但新请求仅查看资料或确认进度时，执行`node "<运行入口>" doctor "<小说项目>" --inspect --compact --json`，只读汇报，不修登记、不派finish、不据旧scope恢复制作。正在执行同一制作任务时，普通进度提问简报后继续原授权，不切换成新目标。

用户明确调用本插件并要求“继续制作”“接手小说”“检查并修复”时先执行：

```bash
node "<运行入口>" doctor "<小说项目>" --compact --json
```

尚未登记时先读 discovery 指向的文档与章稿，已有小说 import，新书 init。先比较doctor.plan的全书起止与现行文档；若本轮终点超出旧全书计划，先用config --start/--end --source按既有依据更新计划，再设置scope，不直接手改主账或静默扩大授权。最新用户指示通过 scope 保存，包含操作类型、范围、来源和实际授予的修订/交付权限。已授权的一批、一卷或全书持续完成，不在每章后重复请示。

首次运行检查模式、全书计划章号、篇幅政策、审查间隔的依据。先利用现有资料；只有 configure 的缺项且资料无法回答时，集中一次询问，如“每章约多少汉字，或按底本篇幅；每几章审查；计划从哪章至哪章”。默认4000字或5章仅是待确认建议，不能静默当要求。把已有来源或用户回答写入 config，再运行 doctor。参数明确且来源有效时不重复询问；等待必要回答时只做不依赖该答案的资料整理。

## 队长与六个子代理

作者明确恢复或给出新终点后，先scope保存最新操作、范围与来源，再派制作单，不等旧范围收尾才记新目标。finish按nextAction.call给出的chapters批量读回现稿，只提取两更与出章状态，不复制、润色或提交正文补丁，不手填复核通过；独立复核保持，写作和返修仍每单一章。

复核每章明确verdict，未受影响的独立通过章保留结论，仅复验未通过及受影响章；旧报告无逐章判决时不推断通过。篇幅按底本且未设比例时，不从历史推导95%门槛。排版返修用format的heading/indent，不重抄全文；draft-check的comparison区分实际内容与格式变化，字数相同不证明文本相同。复核也可通过本任务result.json或正文视图复算正式稿，计量不改变判决。无当前作者依据时不把井号/缩进偏好升级为阻塞。

首次启动岗位时，若当前原生spawn工具支持fork_turns，使用none，只传项目根、任务prompt/context/result路径、runtime入口及必要的作者约束，不复制队长累计历史。作者的新要求先记录进任务依据，不能靠继承聊天补齐遗漏。后续按既有规定复用同岗位代理，复核与文笔始终分离；DSH继续使用受限的新worker，不套用此Codex参数。

当前主会话是队长，只负责诊断、任务单、收集、提交与汇报，不写正文，也不切换帽子假装完成分工。主编、世界、剧情、人物、文笔、复核分别由独立子代理承担；按 nextAction 选择相关岗位，不为每章凑齐六次调用。

使用 Codex 当前提供的原生子代理工具，例如 `collaboration.spawn_agent`、`send_message`、`followup_task`、`wait_agent`；工具命名以当前宿主实际暴露为准。需要启动空闲或已完成代理的新一轮工作时用能唤醒执行的followup_task；send_message只给仍在运行的代理追加信息，不能将排队消息当作已唤醒。有原生 workflow 时可用于组织依赖，实际创作仍交给子代理。保持当前模型与权限，不改全局设置，不创建用户侧新聊天代替内部子代理。达到并发上限就分批等待；缺少子代理能力时保存任务并报告需要启用该能力，不回退到队长代写。

1. doctor选择动作；先完成本章sourceIds/treatment/dependencies与有效细纲映射，再dispatch创建岗位任务，读取返回的任务提示、材料包、结果路径。
2. 首次spawn时只让子代理读取任务单和岗位卡，明确“尚未绑定，只读准备，收到本单绑定成功确认再开始，不写结果、不自行轮询主账”；取得实际ID后立即执行`task --id TASK_ID --status running --agent 实际ID --compact`，成功后用能触发执行的原生followup_task确认“本单已绑定，开始执行”。同一目标复用已完成且已收件的同岗位代理时，先绑定新单再followup_task派发完整路径；未收件前不能绑定下一单，不能更换岗位。复核与文笔始终不同。写作/返修每单一章，finish可批量补记录；策划并行时正式目标不重叠。
3. 子代理仅读指定材料，把结果及辅助文件写到隔离任务目录，不改主账或正式正文。文笔提供正文与两更/出章状态；复核冷读实际版本并填写派单提供的复审草稿，不能只改 true 或照抄作者自评。
4. 等待子代理完成，队长collect验证并串行提交结果。仅字段/引文错误回叫原复核修同一报告，最多3次，不标failed、不新派整批冷读、不由队长代填；三次仍失败就明确报告具体缺口。真实执行失败或取消才用task --reason记录后处理重派。范围相同或缩小时按scope返回的jobs.kept/cancelled保留有效任务，暂停或依据变化先重核，不并发写登记；重复collect已完成任务返回原结果。
5. 使用collect --compact返回的diagnosis立即执行下一步，不能只说“接下来派单”就结束回合。下一步为派单时实际完成建单、绑定和启动；已有子代理运行则原生wait_agent等待并继续收件，等待超时只表示暂无新结果，不表示目标完成。CLI不会替Codex调用spawn，DSH的continuation不是Codex自动派单能力。仅中断恢复或缺少诊断时再doctor；至complete、作者暂停/取消或确需作者回答才结束制作回合。普通问题由岗位子代理在授权内修复；真实工具/权限/材料阻塞需如实汇报具体原因。

review 范围只审不改，pause 保持暂停。返修、待裁决破格、熔断和批次校准都受工具入口约束，不以额外派单绕过停笔。每批通过后派剧情子代理核对当前授权内的下一批细纲、伏笔与事实，登记校准再继续。

返修任务直接附本轮manuscript当前稿，默认提交patches定点修改，保留其他场景和已修正确内容；确需整章重写提供rewriteReason。派单时把实际CLI绝对路径传给子代理；文笔保存草稿或result.json后执行`node "<运行入口>" draft-check "<小说项目>" --task TASK_ID --file 任务文件`取得准确汉字数，这不是工程测试。首次独立重写禁止历史旧稿不自动扩大为禁止修订本轮新稿，作者另有明确限制时遵守。

独立复核verdict仅passed/rework。旧问题在resolutions逐项填open/resolved，resolved必须提供resolution及当前版本真实evidence；collect统一更新问题状态，不再让队长逐项手动关账。红项始终阻塞，黄项默认阻塞，非缺陷的可选建议用info或明确blocking:false并说明理由。已提交返修先局部复验，不重复修待验稿。使用派单的本章与关联细纲切片；相同材料共享读取，不额外通读整册。

## 来源、交付与恢复

复核优先按requiredReads读reviewReadings逐章整合稿和sharedReviewReading共享依据，正文、底本和逐章材料完整保留，不再把packets/textFiles/body中的相同内容各读一遍。旧任务无整合稿时仍按原清单读全。reviewFocus.changedInputs/unchangedInputs只比较正文版本和审阅依据，不代表通过；证据使用正式原稿originalPath，DSH完整阅读回执保持。首稿在文笔任务内集中完成承接、底本笔误、代词动作及时序伤情和重复对白回读，再提取两更并计量，不新增审查岗位或自评表。

等待原生完成通知；需要wait_agent时采用60000毫秒，不循环20秒短轮询、不为报进度另派诊断子代理。没有新成果时不重复播报同一句“仍在制作”，有收件、缺口或需要用户处理时再简报。作者要求固定频率时按其要求。

同一个复核子代理可复用自己已实际读过、来源与任务依据未变的底本和规则；返修后的当前章、问题证据和相关接续仍须实际回读。新复核代理、材料变化或上下文已丢失时读全必需材料，不能把别人的摘要当自己已读。此条不改变DSH全新worker及真实阅读回执要求，不减少独立复核或跨章问题覆盖。

historical诊断表示范围外、与本轮依赖无关的旧登记异常；保持可追溯，不强行修旧稿、不因此重开已通过的新章。受影响的直接前章、显式依赖或当前范围异常仍阻塞制作。nextAction=archive则直接归档，不能因historical列表非空宣称无法完成。

目标完成后的收尾由程序分类归档，不派额外整理子代理。最后收件/交付等完成动作会自动处理；接续旧项目若nextAction为archive，直接执行archive后再报告complete。暂停、未完成、仍有未收件任务时保留现场；doctor --inspect只读，不触发整理。

归档清单见00-状态.md；旧任务用task --id查询归档后目录。默认归档任务/草稿/复核草案/阅读回执，额外过程资料用record material的temporary:true及category登记。正文、现行文档、报告、成书及当前引用不移动，不把陌生文件按名称当垃圾。

现行分册用config.outlines的path/from/to及source一次绑定适用范围，逐章map仍可覆盖；不逐章重复选择同一册。doctor/collect诊断提供nextAction.call（DSH可直接调用），文档检索按需分页。

子代理按prompt和context.requiredReads读全实际输入，复核不回抄contract/stamp；文笔先完成初稿、集中修订后精确计量，已有完整MD/TXT可用draftFile交稿，免重复输出全文。跨章问题affectedChapters与from/to覆盖全部待改正文和出章状态。既有进度文档由程序更新当前状态段，保留原要求与历史，不另建主账或重复询问同步授权。

接手先用`node "<运行入口>" documents "<小说项目>" --kind characters`等命令定位现有资料，再read/grep实际相关段落。标题、目录和预览是检索线索，不能冒充已读全文。多份候选回查现行要求后config的documents绑定已有路径；默认01/03/04/05/06不是必须重建清单。策划artifacts优先target/patches原位补充，无缺口时为空，新建同用途文件说明createReason。select-document由代理分析并map选定现有细纲，不把选择转成无依据的新建。

要求用 record 保存来源、生效章区间和替代历史，作者新指示优先。导入指定会话时用可用会话读取工具提取用户指示、目标变化和最终结果，并与现行文档核实；助手自述不代表作者批准，资料缺口不凭猜测补齐。

partial 标明阶段范围；final 需全书当前版本最终验收。source、analysis、adaptation 分开，原作分析汇编不混入改编方案。格式支持 txt、docx/word、epub、md 及组合，核对实际交付文件。

压缩或中断后读状态并重新doctor，用task --id取已有单的真实路径与状态：pending且无agent时继续启动并绑定该单；running且代理存活时等待，已有结果则先collect；确已失去执行者才记录原因后重派。不能对未启动单盲目collect，也不重复创建相同任务。新会话仍需本次明确调用和实际授权，旧scope不自动启动制作。简报只给实际完成范围、重要修复、交付路径、下一步或必要裁决；工程检查不代替文学判断，阶段完成不称全书完成。

复核子代理结束前，使用上述实际运行入口执行`result-check <项目> --task ID`只读预检，修正原result.json字段/引文后再交队长collect。issues每项含text及evidence:{path,quote}；passed各维grade填A/B及真实reason，不用“良好/合格”，不为校验抬分。quote逐字复制连续短句，不需整段对白。已经完整冷读的原复核只修自己同一报告，队长可通过原生代理跟进入口返回具体错误；不由队长代填、不因字段错误重派整批。真实材料/正文变化仍重新审核受影响范围，不复用他人阅读。
