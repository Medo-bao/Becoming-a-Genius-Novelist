# 六岗位子代理派单


复核单的reviewReadings与sharedReviewReading是按章整合的完整阅读入口；旧packets/textFiles仍存于任务目录供定位，不重复读相同内容。requiredReads由程序列出实际必读文件，DSH读全才可提交。reviewFocus标出相对最近相关复核的依据变化，不能自动填通过或继承别人的已读；证据仍引用原正文。文笔交稿前在本任务中完成一次集中质量回读，保留独立复核。

单会话指作者只使用一个主会话。该主会话是队长，负责诊断、登记、原生派单、收集提交和汇报；六个岗位是独立子代理，不能在队长上下文依次切帽冒充。六岗按需出场，无须每章全部重做。

DSH使用novel_workshop专用工具：dispatch一次完成建单、启动全新worker及真实ID绑定，收到完成通知后collect一次，直接按返回的diagnosis续作。下文的手动原生spawn/task步骤适用于Codex等CLI宿主，DSH不重复执行这些步骤。队长没有shell、直接write/edit、send_message或手动subagent入口；worker真实分页读完任务单、岗位卡、材料包与复核正文后才能写结果，阅读回执由宿主生成并在collect检查。

DSH从只读确认恢复时先doctor options.inspect=false，再立即scope保存作者最新范围，之后才执行诊断待办；不要先处理旧scope的collect/finish，或先scope再撞只读拦截。运行入口与手册只选doctor.runtime返回的实际路径，不重复读稳定副本和源码副本。

## 开工前置（实测踩过的坑）

- **项目没有 `.novel-workshop/project.json` 时，先 `novel import`（既有稿）或 `novel init`（新书）**；登记前不得改任何正文。
- 项目自带的 `进度.json`、`docs/` 台账、`python`/`ps1` 脚本只作历史资料，**不能代替工坊 CLI**，也不要把它们当主流程。
- 派单后等完成通知或 `collect`，**不要用 `Start-Sleep` 或轮询脚本**等子代理；轮询既浪费 token，也会掩盖“任务没启动”的问题。
- 子代理说“没有工具/读不到材料”时，队长先查 worker 预设与任务绑定，**不要替它补写正文**，更不要把它的记忆版正文直接落盘。

| 岗位 | 职责 | 正文权限 |
|---|---|---|
| 主编 | 编辑策划、阶段缺口、改编边界、问题根因与推进建议 | 不写 |
| 世界 | 世界规则、术语、能力/资源限制及冲突分析 | 不写 |
| 剧情 | 总纲、细纲、来源映射、伏笔与批次校准 | 不写 |
| 人物 | 人物档案、关系、知情状态、语言基因 | 不写 |
| 文笔 | 按材料包写作或返修，提供本章两更与出章状态 | 唯一创作者 |
| 复核 | 冷读实际版本，给引文、结论与问题，不改写正文 | 只读 |

## 队长创建并启动任务

```powershell
node .novel-workshop/bin/novel.mjs dispatch . --role 文笔 --action write --chapter 12
node .novel-workshop/bin/novel.mjs dispatch . --role 复核 --action review --from 11 --to 15
```

dispatch 返回 id、role、action、chapters，以及绝对路径 directory、promptPath、contextPath、resultPath。它只建单，不启动模型。队长必须接着调用宿主实际提供的子代理：Codex 使用原生 spawn/send/followup/wait；DSH 固定使用 tiancai-novel-worker 独立预设。当前DSH workflow不能选择受限worker，暂不暴露该入口。不能把JSON任务误报为已启动子代理。首次 configure 缺项未补齐、当前scope暂停时不能派制作单。

Codex首次spawn先让岗位只读准备，取得真实ID并完成以下绑定后，再followup确认开始；DSH已在专用dispatch内预绑定。同岗位代理复用时先绑定新单再通知，旧单必须先收件或取消，不能让同一代理同时执行两单。

绑定宿主实际返回的子代理标识：

```powershell
node .novel-workshop/bin/novel.mjs task . --id TASK_ID --status running --agent HOST_AGENT_ID
```

把任务提示、项目绝对路径、对应 `core/roles/岗位.md` 和结果路径给子代理。模型与权限继承宿主设置，不改全局配置。世界/人物等无依赖分析可并行，且各自正式目标不能重叠；共享文件的修订串行派发。人物/世界结果收集后再派依赖它们的剧情任务。写作/返修每单只处理一章，先collect实际出章状态，再派下一章；仅finish可按现有审查间隔批量补记录，不创作正文。已有文笔单未收集时不派第二单。并发不足就排队等待，队长不接手写作。

复核与被审章稿的文笔必须是不同子代理；不能复用文笔子代理充当复核。可以复用同岗位子代理承接下一张不冲突任务，但每张单单独绑定并收集。

## 子代理工作与结果

策划任务的context.documents列出当前用途、候选文件、标题、目录与短预览。预览只用于定位，不能声称已经全文读完；使用read/grep读取目标相关段落。已有成果可用时artifacts为空；需要修改优先`{target:"原有文档.md",patches:[{before:"唯一原句",after:"新原句"}]}`。现有文档的派单版本变化会拒绝旧结果；原样成果不重写文件。只有确实需要独立文档时填写createReason，不能把默认文件名当成新增义务。需要改变当前入口时由队长config的documents绑定实际依据；不据文件存在推断批准。

子代理只写分配给自己的任务目录，不直接写 project.json、正式正文、两更或报告目录。只读取任务所列材料及必要相关片段；发现缺失来源、相互冲突或作者决定缺口时返回具体原因，不凭空补批准。无需在岗位任务中运行工程测试。

文笔的 result.json：

```json
{
  "title": "第012章 章名",
  "text": "# 第012章 章名\n\n完整章稿内容",
  "notes": "本章新事实和后章提醒",
  "experience": "本轮可复用手法或需要避免的问题",
  "exitState": {"伤势": "左手仍受伤", "物品": "药盒由乙持有"},
  "entities": ["甲", "乙"],
  "factIds": ["F1"]
}
```

write使用完整文笔结果。repair、repair-length、repair-format派单额外提供manuscript当前稿，默认以patches:[{before,after}]替代text，保留未改内容；before须唯一匹配。需要整章重写时提交text与rewriteReason说明。text含章标题，title不代替正文标题。

finish只补当前正文的notes、experience、exitState及可选entities/factIds，不接收text、draftFile、patches或rewriteReason。doctor的finish调用按既有interval给出一批章号，一次派单，context.manuscripts列齐各章完整正文；不附重写用底本和细纲，不重读旧任务或整份经验文件。多章结果为`{"chapters":[{"chapter":章号,"notes":"...","experience":"...","exitState":{...}}]}`，所有章齐全并验证后才按序写入两更，正式正文与版本不变。疑点记入notes，后续独立复核判定；需要正文修改另派repair，补登记不增加审阅通过。

DSH文笔写入或编辑本任务result.json后，宿主自动反馈准确字数与篇幅判断，无需再调用novel_draft；单独草稿仍可用该工具计量。Codex文笔交稿前调用draft-check --task ID --file 文件。两者使用同一个计数函数，支持patches候选稿；finish直接计量正式现稿，也可只读本单正文视图，不复制草稿。无需shell测试或估算汉字数，不开放任意文件或主账写入。

篇幅按底本且minRatio/maxRatio为空时，没有95%等数字门槛，历史比例不构成新要求。完整初稿按场景份量起草；明显内容缺口集中补齐，不逐句添写来跨过自行认定的百分比。文笔反馈的comparison区分文本完全相同、仅格式变化和内容变化，首处内容差异供定位；changeWords=0不能证明其他文字没动，不写计量探针。

排版返修用`format:{"heading":"plain","indent":"fullwidth"}`，支持heading为plain/markdown、indent为none/fullwidth，至少一项；程序直接处理当前稿，不重抄全文。可与patches合用，不与text/draftFile合用。仍提交实际两更与出章状态；只有当前作者明确格式要求才据其阻塞，没有明确硬要求时保留建议，不凭相邻稿增加规则。

复核派单同时生成reviewDraft.data草稿和逐章材料包chapters/NNN.json，context.packets给出绝对路径。长文本移入textFiles列出的UTF-8阅读文件，原生read可按offset/limit分页，避免JSON长行被截断；旧编码底本由队长解码后提供。manuscript指向正文阅读视图，长行只增加阅读换行，正式文件不变；引用选择不跨新增换行的短句，evidence.path仍用originalPath。子代理无需运行prepare命令，DSH worker不提供shell。

补齐verdict、summary、布尔检查项、evidence、grades及必要issues，结果必须覆盖完整任务章号并保留版本与依据。kind由任务动作决定，普通review不能升级final；final-review自动取全书。问题范围必须完全属于被审章节，省略to按from保存，证据来自该范围内的当前被审正文。文学结论由复核实际阅读产生，队长不能代填。

每个chapters条目另填verdict:passed/rework。整单rework时，只要某章由独立复核明确passed、检查项与证据齐全、没有未关闭的本章/跨章阻塞，程序就保留该章通过；改稿或依据变化会使对应通过失效。后续仅复验未通过章及真实受影响的直接依赖，未变且合格的其他章不重派。旧报告未逐章判决时不从检查项true推断通过，最终全书验收仍须完整final-review。

复核使用模板内的宿主字数即可；需要复算时novel_draft/draft-check接受本单result.json或正文阅读视图，按绑定正式稿返回各章字数，不把报告JSON或整合材料全文当正文计量。计量不写主账或阅读回执，也不改变审阅判决。

verdict仅passed/rework。红项必须阻塞，黄项默认阻塞；非缺陷的可选建议以info或blocking:false说明理由，可随passed保留。旧问题在resolutions逐项复验，resolved须给id、resolution及当前被审版本的evidence。收件统一更新状态，作者裁决项不由复核关闭。返修收件后先复验，不把尚待确认的旧问题再派一次修订；复验仍未修好则重新进入repair。1.0.1遗留warned结果按报告中的阻塞问题转换为rework或passed，仍执行全部通过条件与证据校验，避免丢弃实际冷读成果。

复核提出修法前，读取dependencies.linkedChapters所指当前章稿的相关片段，结合跨册材料确认修法没有违反前章约束；对照resolvedIssues保留已确认的修复，推翻旧修法须在问题说明中指出具体变化的证据。跨章问题按完整影响范围复验；review-scope诊断表示该范围超出当前授权，队长集中确认所列ranges，不重复派发无法关账的局部复核。

整册细纲按本章、相邻章、显式依赖与“关联章号”切片并保留卷首共同要求；其他册中的直接关联以relatedOutlines提供，未找到的章号列在missingRelatedChapters，不递归扩展到全书。缺项影响当前任务时向队长说明并补料。无法识别章节标题的短纲保持全文。批次材料中相同长文本共享一个只读阅读文件，完整底本和被审正文仍提供全文。

策划岗位结果：

```json
{
  "summary": "完成的分析、变更依据和需要登记的事项",
  "artifacts": [
    {"path": "第012章细纲.md", "target": "06-细纲/第012章.md"}
  ]
}
```

path指任务目录里的实际产物，target是项目相对目标。来源、目标及任务目录拒绝符号链接和目录联接，不能提交AGENTS.md/AGENTS.override.md等宿主指令文件。内容只读取一次并保留原字节，完整动作校验通过后才提交。outline和calibrate只准修改任务指定的准确细纲路径；普通策划仍可修改岗位负责的其他策划文件。需要登记的事实、要求、映射、阶段门建议由队长调用record/map/gate。

剧情calibrate用doctor给出的--from/--to派单，结果含outline、note及可选artifacts，新建细纲可以与复盘一起提交。审阅ID、章号和来源绑定任务，不能提交chapters伪造作者熔断恢复。作者真实新决定仍由队长单独执行calibrate的chapters/source入口。

## 收集、失败与恢复

目标完成后，程序归档已结束任务、临时草稿、复核草案和阅读回执并更新任务查询路径；成功、失败、取消产物均保留。正式稿、报告、当前规划与被生产登记引用的资料保留；仍运行/待收件任务存在时不整理。工作目录之外的额外临时记录通过material temporary/category登记后分类归档，不让队长或岗位随意移动未知旧文件。

只确认进度使用doctor --inspect，不派任何制作单；正在同一制作任务中询问进度不改变原授权。reconcile/当前章登记失效在finish派单和收件处均拦截，先处理实际登记问题，不绕去补两更。数字TXT的版本按已登记准确路径识别，真实未登记撞号仍拒绝猜采用。

任务提示及context.requiredReads列齐全部必读路径，含复核的嵌套材料与全文。漏读拦截一次列出所有缺项及续读起点，不逐项试交。已有完整草稿可用draftFile替代text；完整读回、版本校验与独立复核不减少。

复核只回传实际判断字段与引文，宿主补齐原派单contract/stamp。跨章问题使用affectedChapters与完整from/to；问题标题明确写出的跨章范围也会合并入登记，避免后章漏修。

import及旧项目接续会发现已有docs/README.md、项目进度、正文执行记录、现行要求与执行计划，程序在这些原文件插入/替换工坊当前进度段，保留原要求和历史。也可config.progressFiles显式绑定现有MD路径或传空数组停用；无需另派岗位抄台账或再次询问维护授权。

```powershell
node .novel-workshop/bin/novel.mjs collect . --id TASK_ID
```

队长收集前确认宿主子代理确实完成并产生文件。collect 验证任务岗位、范围、绑定、结果和当前依据，再串行提交；文笔结果保存新正文版本并完成两更，复核结果生成正式审阅，策划产物落到允许的目标。队长提交既有结果不等于队长创作正文。

已完成任务重复collect返回既有结果，不重复创建版本或报告。失败或取消用task记录状态与原因：

```powershell
node .novel-workshop/bin/novel.mjs task . --id TASK_ID --status failed --reason "宿主子代理执行失败的实际原因"
node .novel-workshop/bin/novel.mjs task . --id TASK_ID --status cancelled --reason "当前任务取消依据"
```

scope范围相同或仅缩小时，章号仍在范围、操作/修订权限及间隔不变且依据有效的文笔/复核单会保留原代理、产物和阅读回执；scope返回jobs.kept/cancelled，按实际结果汇报。暂停、模式/权限或依据变化、任务越界时取消相应未完成单；要求、上游章稿或材料变化时旧结果会被拒绝，处理原因再重派，不能强行提交或伪造完成。

压缩或中断恢复先 doctor，再查询已有任务及宿主状态：已完成未收集的先 collect；仍运行的继续等待；确已失去执行者的记录失败后重派。没有可用子代理工具时保留任务并报告能力缺失，不能把同上下文扮演六岗作为成功结果。

## 原单报告预检与续作

DSH本会话明确scope后，成功collect会自动按当前诊断启动下一岗位，返回continuation时只等待该单完成通知，不重复dispatch或结束等作者催促；未自动启动才执行nextAction.call。自动续作只作用于本会话当前scope，不在scope初次保存时跳过前置资料同步，也不越过configure、作者裁决、导出等动作。scope.options.automatic=false改为手动派单；暂停、只读或中止清除本会话续作状态，获准恢复时重新scope。

复核保存result.json即获得只读预检。issues每项必须含非空text及evidence:{path,quote}，passed的各维grade为A/B并有真实reason；“良好/合格”不能代替字母，程序不替代理抬分。quote用当前稿逐字连续短句，不拼接、省略或补引号，无需整段对白。字段或引文错误保留原单，由原复核代理修同一报告；DSH collect自动回叫原代理，correct-result可恢复，最多3次，不标failed或由队长重建issues。新写作、返修及实质复核仍用独立任务；材料/正文变化则按受影响范围重新审核，不借字段回修绕过。原代理保留自己已验证的完整阅读回执，回修先读prompt/context/岗位卡及原result.json，仅能写result.json；新代理仍须完整读取。

Codex在结束复核前使用`novel result-check <项目> --task ID`，只读校验原结果，不落审阅或关闭问题。字段错误让原复核子代理修同一文件，不能由队长代填；必要时回查对应原句，材料已变则重新派受影响任务。DSH调用上述专用动作，不开放shell或手动send_message。dispatch的review参数仅供calibrate填写真实审阅ID，不承载额外提示词。
