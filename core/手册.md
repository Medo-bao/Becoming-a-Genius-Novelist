# 小说工坊制作手册

核心目标：自动诊断小说状况，在一个主会话中持续完成已授权的制作，减少作者逐章发指令。队长负责流程和收集提交；主编、世界、剧情、人物、文笔、复核由六类独立子代理承担，正文只由文笔创作。CLI 维护文件、范围、版本、来源和状态；派单由宿主原生 subagent 执行（DSH 固定使用受限的 tiancai-novel-worker 预设，不暴露 workflow；Codex 使用原生 spawn）。

DSH在novel_workshop工具内完成CLI动作与原生派单，队长不执行shell或直接写文件。dispatch自动建单/绑定/启动；等完成通知后collect，返回结果与下一步diagnosis，不重复doctor、prepare或accept。Codex仍按CLI与原生子代理步骤运行。独立复核、材料核对、尾批审阅和版本保留均保持。

返修直接附本轮当前稿，默认patches定点修改。DSH文笔写入或编辑result.json后直接获得宿主自动计量反馈，无需再调用novel_draft；单独草稿仍可用该工具，Codex交稿前使用draft-check。独立复核通过resolutions和新版原句确认旧问题，程序收件后关闭；已修待验先复验，不重复派修。实质缺陷必须修复，非阻塞建议可以保留。材料按本章及关联条目切片，完整底本和正文保留；同批相同长文本共享读取。

## 开工、接手与首次参数

效率协议：doctor只返资料摘要，按需documents分页；选定分册后用config.outlines按实际章号范围绑定，逐章map可覆盖。任务prompt/context.requiredReads给完整必读清单。文笔先成完整初稿、集中修订后计量；已有完整草稿可用draftFile交稿。复核无需回抄不可变contract/stamp，同一批已有全文的前章不重复嵌入尾段，实际全文仍必读。

缩小scope仅保留仍有效的文笔/复核单，以返回的jobs.kept/cancelled为准；暂停/越界/权限或依据变化仍停笔。跨章问题必须登记完整影响范围。既有进度文档由程序原位同步工坊状态，无须重新请示或另派抄录任务。

新会话的新请求仅“读取docs、查看或确认进度”时，使用DSH `novel_workshop {"action":"doctor","options":{"inspect":true}}`，Codex/CLI用`novel doctor <项目> --inspect --json`。本轮只读汇报，待办放diagnostics，不修登记、不派finish、不据旧scope自动恢复制作。DSH会话只读期间拒绝制作动作；作者明确要求恢复后doctor的inspect设false，再按真实授权续作，无需追加确认。正在执行同一制作任务时，普通进度提问只作简报，随后继续原授权，不因此切换会话只读模式。

先运行 `novel doctor <小说目录> --json`。未登记时只读识别章稿、0号引子、资料入口及旧进度；已有小说 import，新书 init。不覆盖原稿，不把历史“已写”或助手自述当“已验收”。

读取现行要求、用户最新指示、计划和最近结果，核对四类关键参数：制作模式、全书计划章号、篇幅政策、审查间隔。篇幅可以是固定汉字目标，也可以明确按映射底本处理。已有明确来源直接用 config 登记，缺项集中一次询问；工具默认值不等于用户已规定。用户已明确的参数不再问，不为每个新会话重走立项。

`doctor` 的 configure 带缺项清单。必要答案未到时不开始依赖这些参数的策划或正文制作，可继续整理现有资料。回答与来源保存后再次诊断。立项题材、读者、风格等优先从已有资料提取，只有实际缺失且影响方向时一并询问，不固定重问六道题。

权威状态为 `.novel-workshop/project.json`；`00-状态.md` 与 `.novel-workshop/当前要求.md` 自动生成。原目录、旧进度和经验保留作证据，不维护第二份手工主账。

现有策划文档用documents按用途、标题与目录定位，再读实际相关段落；预览不能当已读证明。默认模板路径不存在时先寻找等效资料，多份候选由代理分析后config绑定，不直接重建。策划任务优先原位补充，已有成果完整时artifacts为空；确需独立文件需说明createReason。select-document表示已有多份章节规划，应分析并map选定，不重新写细纲。

## 授权与阶段门

用 scope 保存最新指示来源、操作类型、起止、修订通过稿与交付权限，每次保留历史：

- continue：范围内持续制作与必要返修，按间隔审阅后继续。
- review：只读回和记录问题，不改正文；有待修项仍可完成本轮审阅，complete 不代表质量通过。
- revise：修订指定已有内容，不新增范围外章节。
- pause：保存状态并保持暂停，旧全书目标不能解除最新暂停。
- export：按有效通过版本交付。

终点变更立即生效，范围外草稿保留，不为凑满一批多写；恢复后沿用已有稿件。G0立项、G1人设/总纲/文风、G2总纲要、G3可执行细纲由队长依据岗位成果和实际批准登记；G4为制作，G5只能由覆盖全书的最终审阅产生。阶段门不是签一个存在文件就完成内容。

## 队长与派单循环

目标完成后的收尾由程序分类归档，不派额外整理子代理。最后收件/交付等完成动作会自动处理；接续旧项目若nextAction为archive，直接执行archive后再报告complete。暂停、未完成、仍有未收件任务时保留现场；doctor --inspect只读，不触发整理。

过程资料归入`.novel-workshop/archive/goal-r授权版本-编号/`，按任务岗位、临时草稿、复核草案、阅读回执和额外清理记录分类；00-状态.md提供归档清单。正文所有版本、现行规划、正式报告、成书、运行资产及当前生产登记仍引用的资料保留原位。任务元数据路径同步更新，正文、证据原句与原始草稿不改写；归档后通过task --id查询新位置，重复collect不再新增版本。

派单字段、结果文件和宿主操作见[派单协议](派单.md)。队长不能靠角色扮演代替子代理，也不能在等待时自行补正文。六岗不是每章固定调用六次：依据实际动作派相关岗位，已有有效成果复用；并发只用于相互独立且正式目标不重叠的资料分析。每张文笔任务只写一章，先收集实际出章状态再派下一章。

| doctor动作 | 队长处理方式 |
|---|---|
| configure | 回查现有来源，集中询问真正缺项，config 保存回答 |
| import / capture-requirements | 接手现有资料，登记明确来源，不扩大授权 |
| plan | 主编子代理分析规划缺口，按需派世界、人物、剧情；队长收集成果、登记阶段门 |
| outline / map-source | 派剧情子代理提供细纲与映射建议；队长提交并继续 |
| write / repair / repair-length / repair-format | 派文笔子代理，带 prepare 材料；collect 提交新版本、两更与出章状态 |
| finish | 派文笔子代理读回实际版本，补齐 notes、experience、exitState |
| review / review-issues / final-review | 派与文笔不同的复核子代理，冷读实际文件，collect 提交审阅与问题 |
| calibrate | 派剧情子代理核对本次审阅后、当前授权内下一批细纲和事实；collect 登记校准 |
| reconcile / repair-record | 核对磁盘与记录，doctor --fix 仅登记遗漏文件，不增加通过结论 |
| reindex-source / refresh-evidence / repair-reference | 回查缺失/变动资料，恢复正确路径或重新索引，复验受影响章 |
| export | 导出指定范围与格式，核对实际文件；缺失产物重新导出 |
| decision / exception-decision / circuit-break | 保存原因、证据及推荐选项，集中问真实作者决定并等待 |
| review-scope | 问题完整影响范围超出当前授权，按返回的ranges集中确认复核/修订范围，不自动越界 |
| complete / paused | 汇报实际结果与必要接续，结束当前授权 |

每个动作后回到 doctor。已有进行中任务先确认宿主状态与结果；依据变化、任务失败或取消时登记后重派，不重复收集，也不让多个子代理并发修改主账。失去子代理能力时保存任务与原因，不能回退成队长代写。

## 本章材料、事实与篇幅

prepare 提供本章细纲、底本切片和行号、前章尾段、入章状态、有效要求、相关事实、到期伏笔、问题、经验与必要阅读路径。派单传路径及相关切片，避免每个子代理全量加载整书。

relatedOutlines补齐跨册直接关联切片，missingRelatedChapters列出未找到的章号，不递归扩读全书；缺项影响判断时先补料。resolvedIssues提供已修摘要，供文笔与复核保留仍有效的修法。复核提出修法前，须核对dependencies.linkedChapters所指当前章稿的相关片段与跨册材料；推翻旧修法要说明具体证据变化，不能只凭前章尾段或新一轮偏好下结论。

事实标明生效范围、实体、实际出处与引文；人物知情、伤势、资源、能力和时间线分别记录。更新用同ID新修订或 supersedes，保留历史。映射支持多 sourceIds 与保留/改写/合并/删除/新增/校正/联动，baselineTreatment 保留首次分类。控制规则只指导创作，不写进人物对白。

按去首标题后的 Unicode 汉字计量。固定篇幅使用作者规定的 words；按底本篇幅时，比例默认只作提示，没有作者要求就不制造固定比例边界。文风依据原作分析、正负样本和人物语言，不能靠重复预案、报数、解释规则凑字数。

## 审阅、停笔与校准

复核子代理必须实际读回当前版本，填写派单附带的 accept 草稿，包括真实引文、模式对应评分和篇幅判断；队长 collect 提交。表格合法与字数接近不能证明文学质量。rework 的问题进入台账，修复由文笔完成；resolved 需证据，retracted 说明误判，superseded 说明新依据。

审阅绑定正文版本、要求、相关事实、底本、细纲、映射、入章状态与依赖章版本/出章状态。上游变化会使受影响审阅失效。阶段稿可采用旧有效通过版，正式全书须最新版本最终验收。历史报告保留。

按 scope 起点和明确的 interval 分批，尾批只审实际章，已修待验可先复验。跨章问题复核覆盖授权内完整已写影响范围，不因批次边界拆成无法关闭问题的局部任务。待裁决破格与返修熔断会阻止写入口，不能仅跳过 doctor 继续写。破格要写清想突破什么、代价与范围，真正批准后才进入材料包。连续 rework 达 maxRepairRounds 时仅暂停当前范围内相关章，记录根因，等待作者校准。

每批通过后，仅对当前授权内实际下一批做校准，核对过的细纲必须存在。calibrate 记录审阅ID、后续章号、note 与 source。熔断恢复则记录作者的新决定、需恢复章号与原因，只重置这些章先前的连续返修计数；不靠篡改阈值隐藏问题。

## 交付与恢复

支持 TXT、DOCX、EPUB、Markdown。partial 标出范围；final 需全书连续完整、当前版本最终验收通过且问题闭合。source 只导出底本，analysis 只收原作来源分析资料，adaptation 才是改编正文。

写入、两更、审阅、任务和范围变更保留状态。压缩或中断后读 checkpoint 与 doctor，核对任务结果和文件再接续，不要求作者重述历史。详细字段与命令见[自动制作协议](自动制作.md)。
