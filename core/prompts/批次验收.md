# 批次复审

运行doctor取得本轮到期范围，再accept创建JSON草稿。按本章实际版本，读底本、细纲、有效要求及相关事实，逐章检查目标、因果、人物声音和场景完整性；引文必须来自当前正文。

原创评价符合要求、剧情逻辑、文字质量；改编另评价改编符合性、删改合理性、文风一致性。篇幅比例只作参照，没有作者要求不自设合格阈值。每项填写判断依据，不能机械把字段全设为true。

问题用真实引文登记，明确可自行修复或需要作者取舍。授权内返修后只复验受影响章；误判撤销并解释，不向正文补造依据。通过后运行doctor继续原授权。末尾不足整批只审实际尾章，不继续凑数。

verdict只填passed/rework；旧问题在resolutions中逐项确认，resolved须有修复后原句与说明，issues仅记新发现。实质问题必须修复，非阻塞建议可保留在通过报告中。禁止只在summary声称旧问题闭合而不填写resolutions。

跨章问题用affectedChapters列出所有需修改正文/出章状态的章，from/to覆盖完整影响范围，不只在说明中提后章。使用任务reviewDraft.data填写文学判断与引文，contract/stamp由宿主从不可变派单依据恢复并核实，无需回抄。
